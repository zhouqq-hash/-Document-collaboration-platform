# AI 审核模板扩展指南

## 1. 设计原则

AI 不负责决定“应该检查什么”，只负责执行系统提供的检查清单。

- 模板是版本化数据，不是一份随文档变化的提示词。
- 模板绑定到文档分类，新版本上传后自动选择。
- 每条规则有稳定 ID、检查说明、严重程度和是否必检。
- 模型必须逐条返回 `pass / fail / unknown` 和材料依据。
- 缺失规则由后端补成 `unknown`，整体结论由后端计算。
- 预审记录保存检查清单快照，后续模板升级不会改变历史结果。

当前内置模板：

| key | 名称 | 规则数 | 用途 |
| --- | --- | ---: | --- |
| `generic_document_v1` | 通用文档质量检查 | 4 | 未配置专用模板时的兜底 |
| `syllabus_v1` | 教学大纲规范检查 | 10 | 教学大纲学时、目标、内容和考核一致性 |

## 2. 新增文档类型

以新增“培养方案”为例：

1. 在 `backend/app/review_templates.py` 新建 `program_plan_v1`。
2. 复用 `COMMON_RULES`，再添加培养方案专属规则。
3. 在分类管理页给“专业培养计划”选择该模板。
4. 用一份正常样本文档和一份包含已知错误的样本做测试。
5. 确认模型输出能被清单校验器补齐和汇总结论。

模板结构：

```python
{
    "key": "program_plan_v1",
    "version": "1.0",
    "name": "专业培养计划检查",
    "description": "检查学分、课程结构和先修关系。",
    "rules": COMMON_RULES + [
        {
            "id": "credit_total",
            "title": "毕业学分总量符合要求",
            "kind": "calculation",
            "severity": "high",
            "required": True,
            "requires_reference": True,
            "instruction": (
                "提取各课程模块学分并合计，与培养方案规定的毕业总学分比较；"
                "展示参与计算的数字。"
            ),
        }
    ],
}
```

大多数新增文档类型只需要增加模板和规则，不需要改页面、数据库或审核状态流。
只有出现新的规则类型时，才需要扩展执行器。

## 3. 规则编写要求

每条规则应满足：

- 规则 ID 稳定、唯一，改动语义时使用新版本模板；
- `instruction` 明确检查对象、比较方法和无法判断的条件；
- `severity` 表示业务影响，不由模型修改；
- `required=True` 的规则失败或无法判断会影响整体结论；
- `requires_reference=True` 时，缺少规范只能返回 `unknown`；
- 不要求 AI 判断颜色、字体、页眉页脚等纯文本无法可靠提取的内容。

推荐规则类型：

| kind | 用途 |
| --- | --- |
| `presence` | 必填章节、字段或材料是否存在 |
| `consistency` | 数据、名称、日期、比例是否前后一致 |
| `calculation` | 学分、学时、比例等可计算关系 |
| `mapping` | 目标与内容、考核、毕业要求之间的支撑关系 |
| `change` | 与上一版本相比的变化和误删 |
| `format` | 可从正文识别的模板字段和命名 |

## 4. 模型输出契约

```json
{
  "summary": "一句话结论",
  "check_results": [
    {
      "rule_id": "credit_total",
      "status": "fail",
      "location": "课程结构表",
      "evidence": "模块学分为 30+40+50，合计 120",
      "explanation": "培养方案要求 160 学分",
      "suggestion": "补充 40 学分或核对课程模块"
    }
  ],
  "previous_issue_checks": []
}
```

后端会：

1. 校验规则 ID，丢弃清单外的检查项；
2. 为漏掉的规则补 `unknown`；
3. 任一项失败则结论为 `risk`；
4. 没有失败但必检项无法判断则结论为 `unknown`；
5. 其余情况结论为 `pass`。

## 5. 模板升级

不要直接修改已经投入使用的模板语义。应新增版本化模板，例如
`syllabus_v2`，再把分类切换到新版本。

历史预审保存了 `review_template_key`、`review_template_version` 和完整
`checklist_json` 快照，因此仍能解释旧记录当时使用了什么规则。

## 6. 验证清单

- 分类 API 能返回所选模板；
- 分类管理页能选择模板；
- 提示词包含完整规则，不包含清单外规则；
- 模型缺少某条结果时会补 `unknown`；
- 失败、待确认、全部通过三种结论都正确；
- 退回后新版本自动关联上次预审；
- 历史记录展示的是当时的清单快照。
