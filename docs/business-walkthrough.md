# 文档管理模块业务方向走查

## 1. 走查目标

在进入真实前后端联调前，用业务视角确认：

- 哪些角色会使用系统。
- 每个角色要完成什么任务。
- 页面之间如何跳转。
- 每个页面需要展示什么、允许做什么。
- 当前原型还缺什么，是否可以冻结后交给技术后端实现。

## 2. 角色与目标

| 角色 | 核心目标 | 主要页面 |
| --- | --- | --- |
| 管理员 | 维护分类和文档，保证文档可管理 | 分类管理、文档列表、文档详情、上传新版本 |
| 文档负责人 | 维护自己负责的文档版本 | 文档列表、文档详情、上传新版本、历史版本 |
| 普通教师 | 查阅和下载教学文档 | 分类列表、文档列表、文档详情、历史版本、下载 |
| 未登录用户 | 登录后进入系统 | 登录页 |

## 3. 核心用户旅程

### 3.1 管理员旅程

```text
登录
-> 分类列表
-> 新建分类
-> 文档列表
-> 新建文档并上传 v1
-> 查看文档详情
-> 上传新版本
-> 查看历史版本
```

### 3.2 文档负责人旅程

```text
登录
-> 文档列表
-> 找到自己负责的文档
-> 查看文档详情
-> 上传新版本
-> 查看历史版本
-> 下载指定版本
```

### 3.3 普通教师旅程

```text
登录
-> 分类列表
-> 文档列表
-> 查看文档详情
-> 查看历史版本
-> 下载当前版本或历史版本
```

普通教师不能看到上传、分类管理等修改入口。

## 4. 页面清单

| 页面 | 主要使用者 | 关键内容 | 关键操作 |
| --- | --- | --- | --- |
| 登录页 | 所有人 | 工号、密码、角色提示 | 登录 |
| 分类列表 | 所有已登录用户 | 分类名称、文档数量 | 进入文档列表 |
| 文档列表 | 所有已登录用户 | 标题、分类、负责人、当前版本、更新时间 | 筛选、进入详情 |
| 文档详情 | 所有已登录用户 | 文档信息、当前版本、权限提示 | 下载、上传、查看历史 |
| 上传新版本 | 管理员、文档负责人 | 文档标题、文件、变更说明 | 上传并生成新版本 |
| 历史版本 | 所有已登录用户 | 版本号、文件名、说明、上传人、时间 | 下载指定版本 |
| 下载确认 | 所有已登录用户 | 文件名、版本号、上传人 | 确认下载 |
| 分类管理 | 管理员 | 分类列表、排序 | 新增、编辑分类 |
| 新建文档 | 管理员 | 标题、分类、负责人、首个文件 | 创建文档并生成 v1 |

当前静态原型已经覆盖前 7 个页面；后 2 个管理员页面需要在下一轮业务迭代中补齐。

## 5. 关键交互与状态

### 5.1 登录

- 输入工号和密码。
- 登录失败时提示“用户名或密码错误”。
- 登录成功后默认进入分类列表。

### 5.2 分类列表

- 展示分类名称和文档数量。
- 无分类时展示空状态和“新建分类”入口。
- 管理员可见“新建分类”按钮，普通教师不可见。

### 5.3 文档列表

- 支持按分类筛选。
- 无文档时展示空状态。
- 支持按标题搜索，后续可增加分页。
- 列表字段：标题、分类、负责人、当前版本、最近更新时间。

### 5.4 文档详情

- 展示标题、分类、负责人、当前版本、更新时间。
- 所有已登录用户可查看和下载。
- 管理员和该文档负责人可见“上传新版本”。
- 其他教师看到只读提示。

### 5.5 上传新版本

- 必须选择文件并填写变更说明。
- 不支持的格式或超过 20 MB 时给出错误提示。
- 上传成功后回到文档详情，当前版本号自动加一。
- 上传记录上传人和时间。

### 5.6 历史版本

- 按版本号倒序展示。
- 历史版本只读，不能覆盖或删除。
- 每个版本都可以下载。

### 5.7 下载

- 下载前展示文件名、版本号和上传人。
- 确认后开始下载。

## 6. 原型验收标准

- 三类角色都能完成各自的核心旅程。
- 页面之间的跳转路径完整，没有死链。
- 管理员、负责人、普通教师的按钮可见性有区别。
- 上传新版本后，版本号正确递增。
- 历史版本信息与上传记录一致。
- 空状态、错误提示、权限不足提示都能被看到。

## 7. 当前原型的缺口

- 缺少管理员“分类管理”页面。
- 缺少管理员“新建文档并上传首个版本”页面。
- 上传过程中还需要补充更明确的加载中和成功反馈。

## 8. 并列原型：任务看板（taskman）

`prototype/taskman/` 是并列放入的第二份原型，它不解决文档管理的问题，而是演示“任务按优先级排序”这件事。

| 项目 | 内容 |
| --- | --- |
| 页面 | 任务看板、任务编辑、任务详情、权重设置，共 4 页 |
| 数据 | 浏览器 localStorage，不经过后端；首次打开自动载入 4 条示例任务 |
| 核心逻辑 | 综合分 = 0.4×紧迫度 + 0.2×难度 + 0.2×工作量 + 0.2×条件；另有手动拖拽排序 |
| 与文档模块的关系 | 无直接关系，属于独立原型，尚未纳入本模块需求 |

待确认事项：

1. 这个任务看板是作为平台功能保留，还是仅作为设计参考。
2. 如果要保留，它归入哪个模块（文档管理、问答管理还是表格协作），需要先补需求说明和验收项。
3. 如果确定要做，后端需要新增任务相关接口（例如 `GET /api/tasks`、`POST /api/tasks`），并把优先级算法从浏览器搬到服务端，保证多人看到的排序一致。

## 9. 交给技术后端的输入

业务原型冻结后，技术后端至少需要拿到：

- 页面清单和跳转关系。
- 每个页面的字段和操作清单。
- 角色权限矩阵。
- 上传文件限制和版本递增规则。
- 错误提示和空状态要求。

对应接口规范见 `docs/api-spec.md`。

4. 技术后端继续补充管理员页面并完善接口联调。
