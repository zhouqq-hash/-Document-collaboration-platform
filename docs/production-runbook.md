# 公网运行与恢复手册

这份手册对应四条验收要求：公网稳定、重启不丢数据、越权操作被拦截、AI 不可用时流程可继续。

## 1. 启动与就绪

```text
Render 启动
  -> flask db upgrade
  -> recover-reviews
  -> bootstrap-admin
  -> doctor --strict
  -> gunicorn
  -> /api/ready 通过后接流量
```

- `/api/health` 只表示进程活着，不访问数据库和存储。
- `/api/ready` 检查核心表可查询、上传目录可读写，失败返回 `503`。
- `doctor --strict` 会阻止公网环境使用默认密钥、临时 SQLite、默认上传目录、
  模拟微信登录或弱口令。

## 2. 数据持久化

必须同时持久化三部分：

1. 数据库；
2. 文档/表格关联的本地上传文件；
3. 备份目录。

`DATABASE_URL`、`UPLOAD_FOLDER`、`BACKUP_FOLDER` 都可独立配置。生产推荐 PostgreSQL +
COS；单实例小规模也可用持久盘上的 SQLite + 本地文件。

## 3. 权限边界

| 操作 | 管理员 | 文档负责人 | 普通教师 |
| --- | --- | --- | --- |
| 查看、下载 | 是 | 是 | 是 |
| 管理分类、创建文档 | 是 | 否 | 否 |
| 上传/回滚所属文档版本 | 是 | 是 | 否 |
| 发起、确认 / 人工兜底预审 | 是 | 所属文档 | 否 |
| 建表格、保存快照、回滚 | 是 | 表格创建人 | 否 |
| 改单元格、正常发言 | 是 | 是 | 是 |
| 隐藏发言、处理举报、管理表格结构 | 是 | 所属内容 | 否 |

越权返回 `403 permission_denied`；需要负责人或创建人的操作按资源归属判断。

## 4. AI 降级与恢复

AI 只是增强项。模型不可用时，系统仍然保留：

- 文档和表格的增删改、版本与回滚；
- 问答发帖、规则汇总、结论；
- 预审失败记录、重试入口、人工兜底确认。

人工兜底必须显式提交 `manual_fallback=true` 和核验说明。AI 原始失败原因不会被清除。
进程中断遗留的排队/执行中任务通过 `recover-reviews` 转成可处理失败状态。

## 5. 排障路径

1. 先访问 `/api/health`，确认进程是否存活。
2. 再访问 `/api/ready`，区分数据库和存储故障。
3. 页面异常时记录追踪号，在服务日志搜索 `request_id=<追踪号>`。
4. 执行 `flask doctor` 检查密钥、路径、账号、Auth 模式和 AI 配置。
5. 预审卡住时执行 `flask recover-reviews`。
6. 数据损坏时停止写入，运行 `flask restore <备份> --yes`，再抽查文档、版本、表格和附件。

## 6. 上线验收记录

- [ ] `/api/ready` 返回 `200 ready`。
- [ ] HTTPS 登录后 Cookie 带 `Secure`、`HttpOnly`、`SameSite=Lax`。
- [ ] 公网配置关闭模拟微信登录，且没有演示弱口令。
- [ ] 普通教师尝试管理员操作返回 `403`。
- [ ] 停用 AI 后可上传文档并完成人工兜底。
- [ ] 重启服务后已有文档、表格、问答和附件仍可访问。
- [ ] 已用 `tools/public_acceptance.py` 完成“写入 → 重启 → 校验 → 越权 403 → 清理”两阶段验收。
- [ ] 已生成备份并在隔离环境完成一次恢复演练。
