# 工作日志 2026-10-23：AI 预审修订闭环

## 目标

把 AI 预审从“生成一份审查报告”补成教师能连续使用的业务闭环：

```text
规范配置 → AI 预审 → 退回待办 → 修订提交 → 针对性复审 → 负责人确认
```

本期只围绕教学大纲修订场景收口，不扩展成完整 OA 审批系统。

## 本次改动

| 项 | 内容 |
| --- | --- |
| 工作流状态 | 文档响应新增 `review_state`：未预审、预审中、待确认、待修改、已重新提交、已通过、预审失败 |
| 退回待办 | 文档详情和文档列表显示预审状态；退回后直接提供“按意见上传新版本” |
| 版本关联 | 预审记录新增 `previous_review_id`，新版本复审自动关联上一版人工退回记录 |
| 复审提示 | 上传页展示上次退回意见和问题清单；上传后详情提示已保留意见并将用于复审 |
| 问题定位 | AI 问题项新增原文/规范依据；结果卡提供当前版本下载入口，便于直接修改 |
| 复审结果 | 模型提示词要求逐项核对上次问题，输出 `resolved / unresolved / unclear` |
| 版本历史 | 每个版本显示预审结论；负责人确认通过的版本标记“已通过负责人确认” |
| 演示数据 | 新增《教学大纲编写规范（2026版）》、一份待修订 Python 教学大纲和一条已退回预审记录 |

## 演示路径

1. 使用 `teacher / teacher123` 登录，进入《Python程序设计课程教学大纲（待修订）》。
2. 查看顶部“待修改”状态、两条带依据的问题和“按意见上传新版本”入口。
3. 上传修订版，确认页面提示“本次是针对性复审提交”以及上次退回意见。
4. 发起复审，查看“上次退回问题复核”中的已解决/未解决状态。
5. 负责人确认通过后，文档显示“已通过”，版本历史保留退回版和通过版。

## 补充：版本化结构化检查模板

- 新增 `review_templates.py`，把审核规则定义为版本化数据，而不是散落在提示词里。
- 新增通用文档模板（4项）和教学大纲模板（10项）；分类通过
  `review_template_key` 选择模板。
- 分类管理页可选择模板，预审记录和版本历史保存模板 key、版本及清单快照。
- 模型只能逐项返回规则结果，后端补齐缺失规则并计算整体结论，避免模型自行增加、
  删除规则或随意决定严重程度。
- 教学大纲模板覆盖：核心内容、前后一致、版本变化、材料依据、必填章节、总学时、
  目标与内容映射、目标与考核映射、考核比例、模板字段。
- 首次浏览器验收发现：结构化清单接入后，预审结果区域没有自动展示；已修复为自动
  渲染最新记录并重新复验。

## 补充：数据库课程审核场景替换与真实模型闭环

原演示数据中的短文本已替换为 5 份可解析的 DOCX 场景材料，另提供 1 份整改稿用于退回后上传：

- 专业培养方案和毕业要求指标点作为上位依据；
- 数据库大纲编写规范同时覆盖学时、目标映射、考核比例和版本字段；
- 待审核稿预设总学时 `72 != 64`、考核比例合计 `90%`、团队目标缺少考核证据；
- 整改稿统一为 64 学时，考核比例为 `10% + 20% + 20% + 50% = 100%`，并补充项目汇报、分工记录和同伴评价。

真实调用还修复了两处闭环问题：

- 兼容模型返回的 JSON 字符串包装，避免检查结果全部落为 `unknown`；
- DOCX 正文按“段落 / 表格”在文件中的原顺序提取，避免模型把章节误判为缺失。

验证结果：

- 首次预审：`risk`，识别总学时、考核比例和团队目标问题；
- 人工退回后上传 v2；
- 复审：`pass`，上次问题全部 `resolved`；
- 人工确认：最终状态 `approved`；
- 全量测试：`227 passed`；
- 自动证据：`testdata/ai-review-smoke-report.json`。
