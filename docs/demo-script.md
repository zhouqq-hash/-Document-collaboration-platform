# 文档管理模块 · 演示脚本

用途：向老师（或评审）演示文档管理模块的功能，目标是在 10 分钟内讲清「做了什么、怎么用、怎么保证质量」。

## 0. 演示前 5 分钟：环境检查

```powershell
cd 'D:\Users\Administrator\Documents\ChatGPT\项目招募：文档协作平台'

# ① 确认 5000 端口没被别的程序占用（如果输出里有 LISTENING，先停掉那个进程）
netstat -ano | findstr :5000

# ② 初始化并启动
.\.venv\Scripts\python.exe -m flask --app backend\run.py db upgrade
.\.venv\Scripts\python.exe -m flask --app backend\run.py seed
.\.venv\Scripts\python.exe backend\run.py
```

浏览器打开 `http://127.0.0.1:5000/`，应该看到原型入口页。

演示前确认三件事：

- [ ] 三个账号都能登录：`admin / admin123`、`teacher / teacher123`、`viewer / viewer123`
- [ ] 准备一个要上传的文件（可以用 `share\演示素材\教学大纲_2026修订版.txt`，也可以用自己的 Word/PDF 文件，≤ 20 MB）
- [ ] 关闭无关窗口，浏览器只留一个标签页

## 1. 开场：30 秒说清背景

> 这个项目是教学文档协作平台，一共规划了三个模块：文档管理、问答管理、表格协作。本期只做文档管理模块，后端用 Flask 提供 JSON API，前端是静态页面直接调用接口。现在这套是能真正跑通的 MVP，不是假数据原型。

## 2. 演示流程（约 8 分钟）

| 步骤 | 操作 | 讲解要点 | 应该看到 |
| --- | --- | --- | --- |
| 1 | 停在原型入口页 | 入口页只有文档管理原型这一个入口；本期只做这个模块 | 一张卡片 |
| 2 | 点进「文档管理原型」，用 `admin / admin123` 登录 | 三个账号对应三种权限：管理员、文档负责人、普通教师 | 进入文档分类页 |
| 3 | 看分类列表 | 5 个默认分类，每个分类显示文档数量 | 专业培养计划 1 份，其余 0 份 |
| 4 | 点「专业培养计划」 | 列表支持按分类筛选 | 表格：标题 ｜ 分类 ｜ 负责人 ｜ 当前版本 ｜ 更新时间 |
| 5 | 点文档标题进详情 | 详情显示当前版本、负责人、更新时间 | 「下载当前版本」「上传新版本」「查看历史版本」三个入口 |
| 6 | 点「查看历史版本」 | 版本按倒序展示，每条都有文件名、变更说明、上传人、上传时间；历史版本只读，不能改也不能删 | v2 在 v1 上面 |
| 7 | 回详情，点「下载当前版本」→ 确认下载 | 这是真实的文件流，不是假链接 | 下载确认页 + 浏览器下载到文件 |
| 8 | 退出，用 `teacher / teacher123` 登录，进详情 → 「上传新版本」→ 选文件 + 填变更说明 → 提交 | **重点**：版本号自动 +1，上传人和上传时间由系统自动记录，不允许伪造 | 版本从 v2 变成 v3，历史里多一条记录 |
| 9 | 退出，用 `viewer / viewer123` 登录，进同一个文档 | **重点**：权限差异。普通教师只能看和下载，没有上传入口 | 页面提示「你当前为只读权限，不能上传新版本」 |
| 10 | （可选）回到终端跑测试 | 关键规则都有自动化测试兜底 | `10 passed` |

第 10 步的命令：

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests -q
```

## 4. 老师可能追问的问题

| 问题 | 回答要点 |
| --- | --- |
| 为什么用 Flask 不用 Django？ | 本模块只提供 JSON API、业务边界清晰，不需要 Admin 和完整 ORM 约定；Flask 更轻，适合先跑通业务。Django 用官方教程项目（`djangotutorial/`）对照学习，不重复实现 |
| 权限怎么设计的？ | 两层：角色级权限看 `users.role`（建分类、建文档），资源级权限看 `documents.owner_id`（能不能给**这份**文档传新版本）。同一个人对不同文档可以有不同的上传权限 |
| 版本号会不会重复？ | 应用层用「已有版本号最大值 + 1」算下一个号，数据库再加 `(document_id, version_number)` 唯一约束兜底 |
| 并发上传会怎样？ | 目前会有一个请求失败（唯一约束冲突抛 `IntegrityError`，未捕获会变成 500）。这是已知问题，改进方向是加锁或重试，我记在了笔记的第 9 节 |
| 密码怎么存的？ | `werkzeug.security` 做哈希，数据库里不存明文 |
| 文件存在哪？ | 本地 `backend/media/`，命名是 `doc_<文档id>_v<版本号>_<毫秒时间戳><后缀>`；数据库只存路径，不存文件内容 |
| 上传限制怎么做的？ | 扩展名白名单 8 种（pdf/doc/docx/xls/xlsx/ppt/pptx/txt），体积上限 20 MB |
| 超过 20 MB 会怎样？ | Flask 返回 413 错误页（HTML），还没有做成统一 JSON，这是已知缺口 |
| 还有哪些没做完？ | 分类管理页、新建文档页、`GET /api/users`、修改文档负责人；另外 `SECRET_KEY` 目前是开发值，上线要换成环境变量 |
| 任务看板（taskman）还在吗？ | 已经撤出原型入口页，文件先留在 `prototype/taskman/`。它是独立原型、不接后端，是否保留为正式功能待确认 |

## 5. 现场出问题的应急处理

| 现象 | 处理 |
| --- | --- |
| 浏览器显示 404 Not Found | 多半是 5000 端口被别的程序占用。先访问 `http://127.0.0.1:5000/api/health`：本项目返回 `{"status":"ok"}`，如果返回别的格式就是这个端口上跑的不是本项目后端，先停掉那个进程再启动 |
| 页面打不开或一直提示未登录 | 不要双击 HTML 文件，必须通过 `http://127.0.0.1:5000/` 访问，`file://` 方式带不了 Cookie |
| 上传报错 | 检查文件类型是否在白名单、是否超过 20 MB |
| 想重新开始演示 | 数据都在 `backend/instance/doc_collab.db`，删掉它再执行 `db upgrade` + `seed` 就能恢复初始数据（注意：会清空所有演示数据） |
| 演示到一半想停服务 | 在运行 `backend\run.py` 的窗口按 `Ctrl+C` |

- **5 分钟版**：步骤 2、4、5、8、9（登录 → 详情 → 上传新版本 → 权限差异）。
