# 项目分工与技术路线

## 1. 工作方向

| 方向 | 主要工作 | 产出 |
| --- | --- | --- |
| 技术方向 | 学习并实现后端框架，负责数据模型、接口、权限、文件存储和测试 | Flask 后端、数据库迁移、接口文档、自动化测试 |
| 业务方向 | 设计功能原型，梳理页面流程和交互 | 墨刀原型或 AI 生成的静态网页原型 |

## 2. 个人角色

当前项目中，我负责技术后端方向，具体包括：

- 学习和使用 Flask 实现后端。
- 设计并实现数据库模型、接口和权限规则。
- 实现文件上传、版本管理和下载。
- 配合接口规范完成前后端联调。
- 编写和维护后端测试。

需求定义、原型评审和最终架构决策由对应负责人确认，后端按确认后的需求与接口规范实现。

## 3. 技术路线

- 项目实现框架：Flask 首选。
- Django：作为对照学习内容，用于理解 MVT、ORM、Admin、认证和迁移机制，不重复实现当前项目。
- 开发数据库：SQLite。
- 文件存储：本地 `backend/media/`。
- 前端：静态 HTML/CSS/JS，业务方向负责原型，后端提供 JSON API。

## 4. 推进顺序

1. 文档管理模块：分类、文档、版本、上传、下载、权限。
2. 问答管理模块：话题、时间线、意见汇总。
3. 表格协作模块：行内编辑、版本记录、历史回滚。

当前只实现文档管理模块，后两个模块待原型和需求确认后再进入开发。

## 5. 协作边界

- 业务方向先确认页面和交互原型。
- 需求与接口规范确认后，技术后端再按接口实现。
- 后端完成一个模块后，通过接口测试和联调验收，再进入下一个模块。
