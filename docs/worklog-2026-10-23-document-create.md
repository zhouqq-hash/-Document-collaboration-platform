# 工作日志 2026-10-23：新建文档流程优化

## 原有问题

- 文档列表没有新建入口，管理员需要回到顶部全局导航才能找到。
- 标题、分类、负责人、说明、版本说明和文件一次铺开，信息层级不清。
- 负责人和版本说明没有默认值，新建常需要重复填写。
- 从某个分类筛选进入后，新建时还要重新选择分类。
- 文件类型、大小和长度约束到提交后才由后端提示，错误主要依赖弹窗。

## 本次调整

| 项 | 调整 | 文件 |
| --- | --- | --- |
| 列表入口 | 管理员在文档列表工具栏可直接“新建文档” | `prototype/documents/documents.html`、`prototype/documents/app.js` |
| 分类上下文 | 从分类筛选进入时，新建页自动选中当前分类；返回链接保留筛选条件 | `prototype/documents/app.js` |
| 表单信息层级 | 拆成“文档信息”和“首个版本”两段，版本说明收进高级设置 | `prototype/documents/create-document.html` |
| 默认值与约束 | 负责人默认当前管理员；标题、说明提供字数计数；新建仍必须生成 v1 | `prototype/documents/app.js`、`backend/app/documents.py` |
| 文件选择 | 支持点击和拖放，显示文件名、大小，提交前校验类型和 50 MB 上限 | `prototype/documents/app.js`、`prototype/documents/styles.css` |
| 错误反馈 | 必填项和非法输入显示在字段附近，服务端错误显示在页内 | 新建文档页面与样式 |

## 验证

- `backend/tests/test_documents.py`：30 个测试通过。
- 浏览器实测管理员从列表进入、分类自动带入、空表单字段级校验、选择文件、创建并生成 v1。
- 普通教师登录后，文档列表不显示新建入口。

## 保留的业务约束

- 本期不引入“空文档草稿”。文档记录与首个文件仍作为一个原子操作创建，避免出现无内容、无负责人或无法进入版本管理的空壳记录。
