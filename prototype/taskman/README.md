# 任务看板原型（taskman）

这是一个**独立**的前端原型：把任务按“优先级算法”自动排序，也可以手动拖拽排序。它不调用后端，所有数据都存在浏览器的 localStorage 里。

## 页面

| 文件 | 作用 |
| --- | --- |
| `index.html` | 任务看板：算法排序 / 手动排序切换、状态筛选、任务卡片列表 |
| `edit.html` | 新建或编辑任务：截止日期、硬性/弹性、难度、工作量、所需条件、状态 |
| `detail.html` | 任务详情，展示该任务算出来的综合优先级分 |
| `settings.html` | 权重设置：四个权重之和必须等于 1.0 才能保存 |

## 代码分层

这个原型值得学的地方是它把三层拆开了，和 Flask 后端的 models / 业务逻辑 / 路由是同一个思路：

| 文件 | 层次 | 对应 Flask 里的什么 |
| --- | --- | --- |
| `js/storage.js` | 数据层 | `models.py` + 数据库读写 |
| `js/algo.js` | 算法层 | 业务规则（算分、排序） |
| `js/index.js`、`js/edit.js`、`js/detail.js`、`js/settings.js` | 页面层 | 路由 + 返回给前端的 JSON |
| `js/seed.js` | 示例数据 | `flask seed` 命令 |
| `css/style.css` | 样式 | 页面样式 |

## 优先级算法

```text
综合分 = 0.4×紧迫度 + 0.2×难度 + 0.2×工作量 + 0.2×条件
紧迫度 = max(0, 1 - 剩余天数 / 30)，硬性日期再 ×1.5（上限 1.5）
难度   = 难度分 / 5
工作量 = 工作量分 / 5
条件   = 被阻塞则为 0，否则为 1
已完成 / 已归档的任务永远排最后
```

算法排序只看分数，手动排序只看 `sort_order`，两者互不覆盖。

## 数据与重置

- 数据存在 localStorage，键名：`tm_tasks`、`tm_weights`、`tm_current_user`、`tm_sort_logs`。
- 首次打开会自动写入 4 条示例任务；也可以点看板上的“载入示例数据”按钮重新写入。
- 换浏览器、换电脑或清理浏览器数据后内容会丢失——这正是它需要后端的原因。

## 运行方式

直接双击 `index.html` 即可，也可以从原型入口页 `http://127.0.0.1:5000/` 进入。

样式使用 Bootstrap 5 的 CDN，需要联网；离线时页面会变成白底无样式，但排序、拖拽等功能仍然可用。

## 注意事项

这个原型不在文档管理模块的需求范围内，是并列存放的独立原型。如果要把它并入正式需求，需要先补需求说明和验收项，再决定是否由后端提供 `GET /api/tasks` 这类接口。
